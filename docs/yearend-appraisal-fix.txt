Year-End appraisal unblock report

Root cause
backend/apps/reviews/services.py:save_form unconditionally required a comparison
entry for every prior_midyear.snapshot.content.commitments ID for MANAGER submissions.
It applied to workflow_version=2 as well as legacy forms, although pillar validation
was already satisfied. Removed that six-line submission gate for both versions.
Reflection-first, five-pillar validation, human assessment, AI permissions,
commitment confirmations, acknowledgements and finalisation remain unchanged.
The existing launch-time requirement for a finalised Mid-Year baseline is unchanged;
this fix addresses appraisal submission, not cycle launch policy.

Dependency/schema audit
Review.prior_midyear -> protected historical Review -> immutable FinalSnapshot.
Review.comparison JSON -> comparison GET privacy rules -> final snapshot
midyear_comparison. These fields preserve historical records, not just a gate.
No gate-only table, field, index or constraint exists. No DB fields/tables removed;
no migrations added. General commitments, development progress, snapshots and
historical comparison.saved audit events are untouched. No production data rewrite.
No production database was accessed or migrated.

API/UI
GET reviews/<id>/comparison/ retained for read-only historical reference.
POST removed (405); ComparisonSerializer and mutation/event-generation code removed.
Comparison page no longer has outcome selectors, rationale editor or save actions.
Review detail identifies the baseline as historical and explicitly says outcomes
are not required for appraisal submission. Existing privacy rules remain in force.
