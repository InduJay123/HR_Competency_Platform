Pillar-target-aware AI coaching

Payload before
  request.input was a JSON-encoded object with period, senior_leader and sources.
  Sources already included complete EMPLOYEE_SUBMISSION, MANAGER_SUBMISSION,
  optional validated task evidence and locked PILLAR_TARGET records. Targets
  were separate from the matching submitted pillar accounts.
  Exact complete synthetic example: docs/pillar-ai-input-before.json.

Payload after
  All existing fields and source contents remain unchanged. Added pillar_reviews
  with context, character, capability, continuity and contribution, each containing:
    target
    success_measure
    expected_behaviour (locked notes, or locked expected_behaviour if present)
    employee_reflection
    head_of_hr_appraisal
    outcome
    steward_judgement
  Exact complete synthetic example: docs/pillar-ai-input-after.json.
  Examples illustrate the exact request.input structure, not production records.
  The webhook envelope is unchanged:
    {run_id, input_hash, request: {model, store:false, instructions,
      input:JSON.stringify(the above object), max_output_tokens:5000,
      text:{format:{type:"json_schema",name:"stewardship_coaching",strict:true,schema:OUTPUT_SCHEMA}}}}
  No mutable PillarTarget row is read. Locked Review.pillar_context is authoritative.
  Legacy reviews without recorded targets still include five entries with null
  expectation fields; missing targets are not fabricated from current values.
  Both original submitted forms remain full sources. No Growth Tools or removed
  participation stage data is added. Existing task evidence rules remain unchanged.
