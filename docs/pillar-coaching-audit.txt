Exact request.input structure
request.input is a JSON STRING, encoding:
{
  "period": {"year": <integer>, "kind": <cycle kind>, "starts_on": <ISO date>, "ends_on": <ISO date>},
  "senior_leader": <boolean>,
  "pillar_reviews": {
    "context": <pillar>, "character": <pillar>, "capability": <pillar>,
    "continuity": <pillar>, "contribution": <pillar>
  },
  "sources": [<source>, ...]
}
Each <pillar> has exactly these keys:
{"target": <text/null>, "success_measure": <text/null>,
 "expected_behaviour": <text/null>, "employee_reflection": <text/null>,
 "head_of_hr_appraisal": <text/null>, "outcome": <text/null>,
 "steward_judgement": <text/null>}
Each source: {"id": <source ID>, "type": <source type>, "content": <original content>}.
Types: EMPLOYEE_SUBMISSION, MANAGER_SUBMISSION, PILLAR_TARGET; existing independent
VALIDATED_EVIDENCE may appear when submitted and validated (not Growth Tools).
Full synthetic example: docs/pillar-ai-input-after.json.
Wrapper: {run_id, input_hash, request: {model, store:false, instructions,
input:<JSON string>, max_output_tokens:5000, text:{format:{type:"json_schema",
name:"stewardship_coaching", strict:true, schema:OUTPUT_SCHEMA}}}}.
Exact OUTPUT_SCHEMA: docs/pillar-coaching-output-schema.json.
