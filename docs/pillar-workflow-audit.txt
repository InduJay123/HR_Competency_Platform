success measure, notes, creator, completion timestamp, version). GrowthEntry gets

legacy fields needed for existing records. No numeric rating column exists.
Keep Review.hr_assessment, acknowledgements, conversation JSON (current commitment
agreement plus history), comparison, responsible-party FKs and all audit events.
Keep development.Commitment: post-review action plan, not cycle targets.
Keep GrowthEntry categories and all unlinked records; not duplicate pillar goals.
Arbitrary reporting mapping was already removed by guarded earlier migrations.
No dedicated obsolete stage schema or superseded target table exists to drop.

Migration policy: existing cycles marked workflow_version=1 without fabricating
targets. New cycles default to version 2. Existing reviews remain unchanged.
Old active cycles finish under their original form contract. A new cycle uses
the pillar workflow; no automatic conversion of submitted/sealed historical data.
No destructive schema operation or production data mutation is planned.
